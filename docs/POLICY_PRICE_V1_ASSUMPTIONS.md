# 政策价 V1 设计假设

> 状态：第一版工程设计假设，尚非用户提供的正式业务制度。用户已授权先由开发方设计政策价第一版；后续如有正式政策口径，以用户确认的规则为准。

## 第一版范围

政策价用于记录某款手机某个配置在某个自然月对应的政策价格。当前不推测或拆分返利、补贴、扣点、任务奖励、结算价等未定义概念。

## 数据维度

一条政策价记录由以下维度识别：

- 商品：`product_id`
- 配置：`variant`
- 生效月份：`effective_month`，必须为该月第一天，例如 `2026-11-01`
- 政策价：`policy_price`，金额使用 NUMERIC(12,2)
- 备注：`note`
- 记录人及记录时间：由服务端注入

## 生命周期规则

1. 同一商品、同一配置、同一月份最多存在一条有效政策价。
2. 作废记录保留，不物理删除；作废后允许重新录入替代记录。
3. 默认查询只返回有效记录；管理员可显式查询作废记录。
4. member 与 admin 均可新增政策价。
5. admin 仅可编辑当前北京时间自然月的有效政策价；历史月份冻结。
6. 历史月份如需纠错，先作废旧记录，再重新录入。
7. 作废必须填写至少 5 个字符的原因，并记录原政策价、作废人和时间。
8. 只允许对在售商品新增政策价。

## 当前尚未定义的业务口径

以下内容没有足够的正式规则支持，第一版不擅自实现：

- 政策价是否包含税费、返利或其他补贴。
- 一个商品配置在同月是否可能存在多种渠道/区域政策。
- 历史月份是否允许补录，以及补录的审批要求。
- 政策价是否需要起止日期、适用客户范围或政策编号。
- 政策价与普通价格的计算关系。

如后续业务需要上述维度，应先确认规则，再扩展模型和迁移，不以备注字段暗中承载结构化业务含义。
