# 政策价 V1 设计假设

> 状态：按用户最新业务说明修订。政策价不是“每月每配置一条”，而是每次政策发布、补充或调整形成一条独立档案。

## 业务定位

政策价用于记录手机渠道收到的每一次政策价格变化。一个自然月内可以存在任意多条政策记录，包括月初政策、月中补充政策、下半月新政策等。系统不按月份或配置限制记录条数。

## 每条政策记录

- 商品：`product_id`
- 配置：`variant`
- 生效日期：`effective_date`，用于准确表达月内不同阶段的政策
- 政策价格：`policy_price`，金额使用 NUMERIC(12,2)
- 政策解读：`interpretation`，必填，记录政策内容、适用范围、关键变化和执行口径
- 补充备注：`note`
- 记录人及记录时间：由服务端注入
- 政策证据：可上传多张宣贯截图，保存原文件、文件类型、大小、SHA-256 摘要、上传人和上传时间

## 证据保存

1. 仅接受 JPG、PNG、WEBP 图片，单张最大 10MB。
2. 服务端校验 MIME 类型及文件签名，不信任客户端文件名。
3. 文件使用随机存储键保存，原始文件名仅作为展示元数据。
4. 数据库保存文件元数据和 SHA-256，用于核对文件完整性及追溯。
5. 证据文件通过登录鉴权接口读取，不公开暴露静态目录。
6. 证据文件不可通过普通业务接口删除；部署时必须将 `POLICY_EVIDENCE_DIR` 指向持久化卷，并纳入备份和恢复演练。

## 生命周期与权限

1. 同商品、同配置、同月允许存在多条政策记录；同一天也不做唯一性限制。
2. 默认查询只返回有效记录；管理员可显式查询作废记录。
3. member 与 admin 均可新增政策记录、上传和查看证据。
4. admin 仅可编辑当前北京时间自然月的有效记录；历史月份冻结。
5. 历史月份如需纠错，先作废旧记录，再重新录入，原证据仍保留。
6. 作废必须填写至少 5 个字符的原因，并记录原政策价、作废人和时间。
7. 只允许对在售商品新增政策记录。

## 迁移兼容

旧版本只有月份字段，没有精确生效日期和独立政策解读。迁移时将旧记录的生效日期设为原月份第一天；旧备注迁入政策解读字段，无法还原的内容标记为历史记录说明。旧唯一索引会被移除，历史记录不会删除。

## 尚未定义的业务口径

以下内容暂不臆造，后续有实际需求再确认：
- 是否需要区分政策发布日、生效日、截止日。
- 是否要记录政策编号、发布部门、渠道/区域/客户适用范围。
- 是否要支持 PDF、Word、Excel 等非截图证据。
- 是否允许历史月份补录，以及补录审批要求。
- 政策价是否包含税费、返利、补贴或其他扣点。
- 政策价与普通价格的计算关系。
