# 手机报价系统 V1 重建计划

> 本文是当前报价系统的工程执行清单。当前范围以用户最新明确的产品边界及《手机报价系统—价格档案核心改造开发规范 v1.0》为准；进销存属于未来独立项目，不属于本仓库、本数据库或本次上线范围。

## 产品定位与边界

本系统是**手机价格档案系统**，不是商品销售平台，也不是进销存系统。核心目标是记录价格、查询价格、比较价格、追溯价格变化。

### 当前系统范围

- 手机商品档案。
- 普通价格记录及完整价格历史。
- 月度政策价。
- 按月、年、日期区间、指定日期 as-of 查询。
- 普通价格与政策价比较。
- CSV 导出。
- 用户权限、操作审计及历史追溯。

### 明确不属于当前系统的功能

- 销量存档、销售订单、销售统计。
- 库存、采购、入库、出库、调拨、盘点。
- 应收应付、客户销售结算等进销存业务。
- 入网台账、月度快照等未被用户确认为当前必需的扩展功能。

**进销存将在下一阶段作为独立系统另行规划和开发**，拥有独立代码仓库、数据库、部署配置和权限体系。未来如有明确需要，可以通过受控 API 对接商品基础信息；不得把进销存业务表或流程直接并入本报价系统。

## 基础价格调整规则（新增业务口径）

1. 普通价格档案中的“基础价格”代表当前基础报价口径；基础价格发生调整后，调整后的金额立即成为新的基础价格。
2. 调价不覆盖旧记录。每次调价均新增一条不可变的价格记录，旧基础价格继续保留在历史中。
3. 新记录的价格归属仍为“基础价格”，同时标记为“调价后基础价格 / 基础价格调整”，并记录生效日期、调价说明、录入人和录入时间。
4. 页面应明确区分“当前基础价格”和历史上的“调价前基础价格”，历史记录按生效日期展示；查询某一天的基础价格时，取该日及之前最近一条有效的基础价格记录。
5. 政策价仍是独立档案，不因基础价格调整而自动改变，也不覆盖基础价格；两者展示、查询和比较时必须明确标注价格口径。
6. 作废错误的调价记录后，系统应按剩余有效基础价格记录重新确定当前基础价格，不能物理删除或直接改写历史金额。

## 不可破坏的约束

1. 价格记录数值写入后不可修改；管理员也不能修改数值。
2. 价格记录作废必须保留原记录、作废人、作废时间和原因；默认查询排除作废记录，审计查询可包含。
3. 商品只允许停用/恢复，不物理删除；关联关系使用 `ON DELETE RESTRICT`。
4. 所有已登录角色可查看全量业务历史；权限只限制动作，不做品牌或区域数据隔离。
5. 会员可以新增当前范围内的业务数据，但不能修改、删除、作废；管理员可执行规范授权的管理动作。
6. 价格与金额使用 Decimal / NUMERIC，不使用浮点数计算。
7. 时间统一使用 Asia/Shanghai 业务时区；记录人、记录时间由服务端注入。
8. 生产 PostgreSQL 16，开发 SQLite；查询逻辑保持两库兼容。
9. API 与 APScheduler Worker 分进程；V1 API 单 worker，不引入 Redis。
10. 不开发或引入销量、库存、采购、销售订单等进销存功能。

## 分阶段执行

### R0 — 基线与工程骨架
- 新建独立分支，不覆盖 main。
- 明确目录结构、环境变量、依赖版本和本地测试方式。
- 清理旧代码设计中的危险默认值、物理 DELETE 和自动建表启动逻辑。
- 引入 Alembic，生产启动不自动建表。

### R1 — 数据模型与迁移
- 当前核心模型：users、products、price_records、policy_prices、audit_logs。
- 完整数据模型字段以 v1.0 可见 DDL 为准；截断或未提供的字段先做最小实现并标记待确认。
- 外键 RESTRICT、软停用/作废、created_at/recorded_by 服务端注入。
- 不为未来进销存预建库存、采购、销售等数据表。

### R2 — 认证、权限、审计
- scrypt 密码哈希；JWT HS256，包含 uid/role/ep。
- token_epoch 强制下线；禁用账号即时失效。
- admin/member 动作门禁；越权尝试写 denied 审计。
- 不提供业务 DELETE 路由。

### R3 — 价格档案服务
- 追加价格记录；价格数值不可变。
- 价格作废保留完整追溯信息。
- 按月、年、日期区间、指定日 as-of 查询。
- 政策价按已明确的第一版设计实现，并将尚待确认的规则标记为设计假设。

### R4 — API 与前端
- 商品档案、价格录入、历史查询、价格比较、角色页面。
- CSV 导出及导出权限。
- 前端只负责交互和展示，权威金额计算在后端。

### R5 — 运行与部署
- 独立 Worker、PostgreSQL 16、Nginx HTTPS、备份恢复演练。
- 资源限制适配约 2GB 内存主机。
- 先备份旧环境；新环境验收后再切流量，不提前删除旧容器和数据。

## 验收门槛

- 价格记录不能 UPDATE 数值，不能 DELETE。
- 商品、用户、业务记录不能物理删除。
- 会员所有 admin-only 请求均返回 403 并写审计。
- 价格历史的 month/year/range/as-of 查询有边界测试。
- SQLite 与 PostgreSQL 的核心查询测试一致。
- 全量测试通过、迁移可从空库执行、备份可恢复后才允许部署。

## 当前已知待核实项

- v1.0 文档在 price_records DDL 中途截断；其他部分字段未全部提供。
- 政策价第一版采用最小模型，具体业务口径仍以用户后续确认或补充规范为准。
- 浏览器端端到端测试、PostgreSQL 16 集成测试及生产部署验收仍需完成。
