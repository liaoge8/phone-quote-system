# 手机报价系统 V1 重建计划

> 本文是重建过程的工程执行清单。业务约束来自用户提供的《开发规范 v1.0》及第三批交付说明；凡原文未完整定义的字段和规则，均标记为待核实，不以旧代码推断。

## 目标

把系统重建为内部价格档案系统：价格记录追加写入、可按时间检索、记录操作人和时间；任何业务数据不提供物理删除能力。

## 不可破坏的约束

1. 价格记录数值写入后不可修改；管理员也不能修改数值。
2. 价格记录作废必须保留原记录、作废人、作废时间和原因；默认查询排除作废记录，审计查询可包含。
3. 商品只允许停用/恢复，不物理删除；关联关系使用 `ON DELETE RESTRICT`。
4. 所有已登录角色可查看全量业务历史；权限只限制动作，不做品牌或区域数据隔离。
5. 会员可以新增业务数据，但不能修改、删除、作废；管理员可执行规范授权的管理动作。
6. 价格与金额使用 Decimal / NUMERIC，不使用浮点数计算。
7. 时间统一使用 Asia/Shanghai 业务时区；记录人、记录时间由服务端注入。
8. 历史月份归档采用不可覆盖的 revision 快照；新 revision 不覆盖旧 revision。
9. 生产 PostgreSQL 16，开发 SQLite；查询逻辑保持两库兼容。
10. API 与 APScheduler Worker 分进程；V1 API 单 worker，不引入 Redis。

## 分阶段执行

### R0 — 基线与工程骨架
- 新建独立分支，不覆盖 main。
- 明确目录结构、环境变量、依赖版本和本地测试方式。
- 清理旧代码设计中的危险默认值、物理 DELETE 和自动建表启动逻辑。
- 引入 Alembic，生产启动不自动建表。

### R1 — 数据模型与迁移
- users、products、price_records、policy_prices、audit_logs。
- 完整数据模型字段以 v1.0 可见 DDL 为准；截断或未提供的字段先做最小实现并标记待确认。
- 外键 RESTRICT、软停用/作废、created_at/recorded_by 服务端注入。
- 后续扩展 monthly_snapshots、tenna_records、sales_archives 前先核对字段口径。

### R2 — 认证、权限、审计
- scrypt 密码哈希；JWT HS256，包含 uid/role/ep。
- token_epoch 强制下线；禁用账号即时失效。
- admin/member 动作门禁；越权尝试写 denied 审计。
- 不提供业务 DELETE 路由。

### R3 — 价格档案服务
- 追加价格记录；价格数值不可变。
- 价格作废/撤销作废及更正链。
- 按月、年、日期区间、指定日 as-of 查询。
- 月度快照 revision 与首屏聚合查询。
- 政策减让额语义按已提供交付说明暂定为 policy_deduction；若完整业务规则另有定义，以明确规则为准。

### R4 — API 与前端
- 商品档案、价格录入、历史查询、首屏卡片、角色页面。
- CSV 导出及导出权限。
- 前端只负责交互和展示，权威金额计算在后端。

### R5 — 运行与部署
- 独立 Worker、PostgreSQL 16、Nginx HTTPS、备份恢复演练。
- 资源限制适配约 2GB 内存主机。
- 先备份旧环境；新环境验收后再切流量，不提前删除旧容器和数据。

## 验收门槛

- 价格记录不能 UPDATE 数值，不能 DELETE。
- 商品、用户、业务记录不能物理删除。
- 会员所有 admin-only 请求均返回 403 并写审计。
- 价格历史的 month/year/range/as-of 查询有边界测试。
- 快照 revision 1 不因后续源数据变化而改变。
- SQLite 与 PostgreSQL 的核心查询测试一致。
- 全量测试通过、迁移可从空库执行、备份可恢复后才允许部署。

## 当前已知待核实项

- v1.0 文档在 price_records DDL 中途截断；policy_prices、audit_logs、monthly_snapshots 等完整字段未全部提供。
- 第三批交付说明称 variants 历史报价搬迁脚本未完成。
- 历史交付说明中的快照、政策价字段和查询规则，需逐项与 v1.0 已知约束核对。
