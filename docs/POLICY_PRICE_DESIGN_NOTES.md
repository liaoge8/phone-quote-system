# 政策价模块：已知规则与待确认项

本文只固化《手机报价系统—价格档案核心改造开发规范 v1.0》中已明确的业务规则，不替代原始业务 DDL。

## 已明确规则

1. member 可以新增本月政策价数据；admin 可以执行规范授权的管理动作。
2. 历史月份政策价跨月冻结，不能直接修改；需要先作废，再重新录入。
3. 当月政策价允许 admin 直接修改。
4. 会员不能修改、删除或作废已录入的政策价。
5. 业务数据不得物理删除；错误数据通过作废标记保留历史。
6. 操作人和记录时间由服务端注入，越权操作应写入 denied 审计。
7. 全部角色查看全量历史，不按品牌或区域隔离。

## 实现前必须补齐的业务定义

当前交接文本未完整提供 policy_prices 的 DDL，以下信息不得从旧代码或第三批说明推断：

- 政策价记录的业务维度（商品、版本、渠道、客户或其他组合键）。
- 字段清单、字段类型、金额精度、必填/可空规则。
- “本月”以哪一个业务日期字段判定，以及跨月边界的时区口径。
- 同一业务维度、同一月份是否允许多条记录，以及重复录入处理规则。
- 作废后重录是否需要关联原记录或填写作废原因。
- 当月 admin 修改是否需要保留修改前后的字段快照及审计详情。
- 查询接口的筛选、排序、分页及导出字段。
- 是否存在政策价计算公式、减让额或与商品价格记录的关联规则。

## 建议验收场景（规则已知部分）

- member 新增政策价成功，记录人由 token 注入。
- member 修改、删除、作废政策价均返回 403 并记录 denied。
- admin 修改当月政策价成功，审计保留修改动作。
- admin 修改历史月份政策价被拒绝；历史数据只能作废后重新录入。
- 作废记录默认不出现在普通列表，但管理员审计可追溯。
- 以 Asia/Shanghai 业务月份验证月末/次月初边界。
- SQLite 与 PostgreSQL 对月份判断的结果一致。

## 当前结论

在完整 policy_prices DDL 和上述业务维度未确认前，不创建猜测性的 ORM 表结构或 API payload。先完成时间边界测试与公共权限/审计基础，再接入正式模型和迁移。
